# i18n — English + Spanish UI

## Objective

Add Spanish as a selectable UI language across MeetingLive, on top of the existing (and already largely built) WinUI localization plumbing.

## Problem

User asked to implement i18n across "the whole app". A scope scan (workflow `wf_a3712d60-bf2`, 2026-09-22) found:

- `MeetingLive.App` already routes every XAML attribute through `x:Uid` and every C#/ViewModel string through `AppStrings.Get`/`Format`, backed by `MeetingLive.App/Strings/en-us/Resources.resw` (~500 entries). Only `en-us` exists; no second language, no in-app language switcher.
- `MeetingLive.Core` (class library, no XAML) has **zero** localization infra. ~30-40 genuinely user-facing strings live as raw literals in: `CliFailureMapper.cs`, `ChatContextPacker.cs`, `ChatRecipeCatalog.cs` (recipe `Name`s), `ModelCatalog.cs` (Speed/Quality/UseCase labels), `TranscriptionLanguageOption.cs` (DisplayNames).
- Packaging is single-project MSIX (`Package.appxmanifest` has `<Resource Language="x-generate"/>`), so a new `Strings/es/Resources.resw` folder is auto-picked up by PRI generation — no manifest changes needed.

## Why

User explicitly requested Spanish + English support with an in-app Settings selector (not just following the OS language), confirmed via AskUserQuestion.

## Explicitly out of scope (user-confirmed)

- `MeetingMarkdownFormatter.cs` / `SummaryMarkdownSplitter.cs` / `SuggestedMeetingTitle.cs` markdown section headers (`## Transcript`, `## Summary`, ...) — these are dual-purpose parse tokens for saved `.md` files, not UI chrome. Translating them would break re-opening existing meetings.
- `CliSummaryPromptBuilder.cs`'s existing `IsEnglish()` bilingual branching — that controls the *generated summary's* language, a separate feature from the app UI's language.
- `NoteTemplateCatalog.cs` instruction paragraphs — LLM prompt instructions, not shown to the user as UI.
- `MainWindow.xaml` `Title="MeetingLive"` — product name, not translated.

## Constraints

- C#12 classic `[ObservableProperty]` private-field syntax (project pin, `LangVersion 12.0`).
- Do not hardcode new UI strings (AGENTS.md architecture note).
- Skills hard gate (AGENTS.md): load exact `SKILL.md` paths before matching work — see per-task routing below.
- Build/test per-csproj only, never `MeetingLive.sln` (`MSB4126`).
- Commits: conventional commits, no AI attribution, direct to main per work unit (repo convention).
