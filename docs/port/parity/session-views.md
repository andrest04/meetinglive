# Parity ledger: session-views

Spec: `docs/port/specs/session-views.md`. Section 8 has 160 items; every one is below. This ledger is updated per package. sv-1 (rules in core) is done. Status words: `done`, `improved` (a section 7 fix changed the behavior), `dropped` (reason given), `pending` (a later package, sv-2 to sv-7, owns it). Rows for items owned by the transcription or library modules say so.

## Decisions

1. Rename is blocked while a run targets this meeting (B4). The suggest-title half of the old rule is dropped with the feature.
2. `renameMeeting` raises `meetingChanged` (B11). The workspace holds no title for the last processed meeting, so nothing else is updated.
3. `busyReason` reports `capture` before `run` when both hold.
4. The slide tracker starts at the opened tab and moves on every navigation (B15).
5. Suggest title (items 36 to 51) and the nav pane grip (145 to 152) are dropped by the owner decision of 2026-11-03.

## Bugs fixed

- B7 (sv-3): a run that ended while the user was elsewhere keeps its result per meeting and `retranscription.getState` returns it.
- B18 (sv-3): cancel versus failure is decided when the failure is recorded; five-outcome precedence tests.
- B17 (sv-3): one ordered main-to-renderer path; state idle is broadcast before finished (test).
- Parity 91 (sv-3): Re-transcribe is refused while a take is being recorded.

- B4: rename during a run is blocked (`renameMeeting` returns `blocked`, `canRename`).
- B11: rename raises `meetingChanged` (regression test).
- B15: slide direction uses a previous index updated on every navigation, starting at the opened tab.
- B16: `busyReason` lets the UI explain a greyed Re-transcribe button (the message is drawn in sv-6).
- B19: dead code (`TranscriptPageViewModel.Title`, `NoTranscriptsYet`, unused resources, null id branch) is not ported.
- B12 (suggest-title state handling): dropped with the feature.
- B20 (sv-2): `session.getView` counts a missing, unreadable or zero-byte audio file as no audio (adapter `fileExists` checks size > 0), so Re-transcribe is not offered for an empty recording.
- B4/B11 (sv-2): `session.rename` passes the transcription controller's runner state, so a rename during a run for that meeting returns `blocked`, and a rename raises `workspace.meetingChanged` through the IPC path (handler tests).
- B13 (sv-2): a missing meeting, path or file never throws on reveal; the channel answers `revealed: false`.

## sv-3 notes

- Runner keeps the last result per meeting (`lastResults`, `dismiss`); cleared when that meeting's next run starts. `retranscription.getState` now returns `{isRunning, meetingId, status, lastResults}`; new request `retranscription.dismiss {meetingId}`. sv-6 reads them when the session opens and dismisses after showing the notice.
- Busy port: `TranscriptionControllerDeps.isCaptureActive`, wired to `workspace.state.isCaptureActive` in `main/index.ts`. Availability returns Busy and start refuses while a take runs.
- Status `left` marks items whose logic lives in the summaries or recording module; the row says where it is verified.
- RED-first: the B7 runner tests, the busy test, the snapshot test and the dismiss handler test failed before the code. The B18 and B17 tests passed on arrival, since the existing runner already captured the cancel flag when the failure was recorded and already reset before Finished; they stay as regression proof.

## sv-2 notes

- Channels: `session.getView {id}` returns `{record|null, hasTranscript, hasAudio}`; `session.rename {id,title}` returns `{status}` (renamed, unchanged, blocked, missing); `session.revealFile {id}` returns `{revealed}`. Handlers in `apps/desktop/src/main/ipc/session-handlers.ts`, wired in `main/index.ts`. An unparsable meeting file reads as no meeting, like `library.getMeeting`.
- Sibling `.wav` fallback (items 7, 157) happens in the markdown parser, so `record.audioFilePath` is already resolved when `session.getView` checks the disk.
- Meeting deleted while open: `workspace.meetingDeleted` is broadcast on delete; covered by the existing `library-handlers.test.ts` (asserts `workspace.meetingDeleted` is sent). The page reaction comes in sv-4.
- Markdown persistence (153 to 157): audited against `library/meeting-markdown.test.ts` and `platform/library/markdown-meeting-repository.test.ts`. Frontmatter order, first-colon split, required id and recordedAt, CR/LF flatten (B3), headerEscaping byte for byte, sibling wav fallback, and Jev, Brief and event keys kept on rewrite are all covered. No test added.
- RED-first: the handler test was written before `session-handlers.ts` and failed on the missing module.
