# Parity ledger: calendar-detection

Spec: `docs/port/specs/calendar-detection.md`. Section 8 has 144 items; every one is below. This module is reduced by the owner's scope cuts of 2026-11-03: calendar reading, Coming up, reminders, event-started takes, event metadata linking, Calendar settings and the pre-meeting brief are not ported. Meeting call detection, its floating popup, the in-app call bar, the popup setting and the meeting app suggestion stay.

Status words: `done`, `improved` (a section 7 fix or a recorded decision changed the behavior), `dropped` (reason given), `pending-real-validation` (what is needed). `pending (cd-N)` means a later package of this module owns the row and replaces it with the final status. Reason for every dropped item: owner decision 2026-11-03, may return later.

## Decisions

1. **Calendar probe stub is left alone.** `packages/core/src/device/calendar-probe.ts` and `native/vozella-native/src/calendar.rs` (a counts-only capability probe) stay as they are: not extended, not removed, not called by this module. Dropped: owner decision 2026-11-03, may return later.
2. **On-disk compatibility.** Settings keys `typeSafeEnabled`, `calendarNotificationsEnabled`, `disabledCalendarIds`, the `Xai` provider value, the event frontmatter keys and the `## Brief` section are read and rewritten without loss. Proven by the round-trip tests under Tests added by this package.
3. **Nothing in this module reads a calendar.** No code path calls the probe or any appointment API.
4. Decisions of cd-2 to cd-8 are appended here by their packages.
