### Decisions

- sp1-D1: closing the window still exits the app (items 11 and 170). No close-to-tray. The tray exists to restore the window after the recording start minimizes it.
- sp1-D2: solid window background (stack.md), not Mica.
- sp1-D3: window state is its own file, `window-state.json`, in the app data folder.
- sp1-D4: at a fractional display scale Electron returns a size a few DIP off from the one it was given (1100 x 720 came back 1106 x 724 from the constructor, 1102 x 721 from `setBounds`), and a state saved from that read grew by that amount on every launch (observed: 1100, 1106, 1112). `createMainWindow` sets the bounds again after construction, and `steadyWindowState` keeps the opened size when the read differs by 4 DIP or less, so save and restore reach a fixed point. A real resize of 5 DIP or more is saved.
- sp1-D5: launch arguments are accepted and ignored (item 10).

### Decisions

- sp2-D1 (item 101): Preparing counts as protected work. Closing waits up to 30 s for the start or import in flight to reach a stable phase (Recording or Processing), then the usual stop and save runs. An import is not cancelled, so the converted file is never lost. If the start or import does not settle in 30 s the guard reports not saved, and the existing 'could not be saved' dialog offers Close anyway or Keep open. No new dialog; the 'Saving your recording' progress shows (no confirmation, because nothing is recording yet).
- sp2-D2: `crash.log` is replaced by `main.log` with rotation (improvement). Nothing is written to `%LOCALAPPDATA%\MeetingLive`.
- sp2-D3: migrations (the library runtime) run before the window is created, because the IPC handlers read the library. Their error is queued and shown after the window is visible, which keeps the observable WinUI order.
- sp2-D4: `before-quit` fires even when the gate then says keep open, so the old bare `before-quit` listeners disposed the audio controller, transcription and detection after a vetoed quit while the user kept recording. They now run from `stopOnExit`, only on an approved quit.
- sp2-D5: the call watcher logs only the error type (`errorType`), as in item 150.
- sp2-D6: a settings file's unknown `uiLanguage` leaves English, matching the C# 'leave the culture alone'.

### Live copilot reconciliation (items 79 to 88, section 6 LiveCopilotPillDockTests)

It fires on every recording change and every main-window focus change. `showStartedHint` is true once, on the false-to-true change. `mainWindowActive` is false right after the handoff minimizes the window. `showPill` is `shouldShowRecordingPill(isRecording, mainWindowActive, handingOff)`.

- `liveCopilotPillEdge` and `liveCopilotPillAlong` are already read, defaulted (right, 0.5) and rewritten by the settings store; a legacy X/Y pair is kept, never written (item 147).
- The popup is dismissed by the handoff on the recording start, so the pill and the popup never show together.
- Reviewer check: after merging both, `shell-platform.spec.ts` must still pass with a pill window present (the main-window lookups in the spec skip `meeting-prompt.html` only), and the pill must register itself, or the window count after close will differ.
