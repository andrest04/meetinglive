### Decisions

- sp1-D1: closing the window still exits the app (items 11 and 170). No close-to-tray. The tray exists to restore the window after the recording start minimizes it.
- sp1-D2: solid window background (stack.md), not Mica.
- sp1-D3: window state is its own file, `window-state.json`, in the app data folder.
- sp1-D4: at a fractional display scale Electron returns a size a few DIP off from the one it was given (1100 x 720 came back 1106 x 724 from the constructor, 1102 x 721 from `setBounds`), and a state saved from that read grew by that amount on every launch (observed: 1100, 1106, 1112). `createMainWindow` sets the bounds again after construction, and `steadyWindowState` keeps the opened size when the read differs by 4 DIP or less, so save and restore reach a fixed point. A real resize of 5 DIP or more is saved.
- sp1-D5: launch arguments are accepted and ignored (item 10).
- sp1-D6: the tray reuses `LiveCopilot_OpenApp.ToolTipService.ToolTip` (Open Vozella). New keys `Ui_TrayQuit` and `Ui_TrayRecording` exist in `ui.en.json` and `ui.es.json`.
- sp1-D7: the recording state comes from `recording.gate.onChange` (phase `Recording` or `Stopping`), which is the main-side `isRecording`.

### Bugs fixed

- Bug 9: one activation helper restores a minimized window (second launch, tray, popup Start, close gate).
- Bug 13: minimum size is Electron DIP, no first-monitor scale.
- Bug 14: icon path is absolute and independent of the working directory.

### Seam for live-copilot (reconciled in sp-5)

In `index.ts` the `RecordingHandoff` instance is the local `handoff`. The pill module should:

- subscribe with `handoff.onHandoff(({ isRecording, mainWindowActive, showStartedHint, showPill }) => ...)`: show or hide the pill from `showPill` (collapse the panel when `isRecording` is false) and play the hint when `showStartedHint` is true. The event fires on every recording change and on every main-window focus change;
- register the pill window with `handoff.registerSecondary(window)` so it closes with the main window (item 89);
- read `STARTED_HINT_DURATION_MS` (2500) from `@vozella/core` for the hint length.

The handoff already minimizes the main window and dismisses the popup. No pill window is created here.

### Decisions

- sp2-D1 (item 101): Preparing counts as protected work. Closing waits up to 30 s for the start or import in flight to reach a stable phase (Recording or Processing), then the usual stop and save runs. An import is not cancelled, so the converted file is never lost. If the start or import does not settle in 30 s the guard reports not saved, and the existing 'could not be saved' dialog offers Close anyway or Keep open. No new dialog; the 'Saving your recording' progress shows (no confirmation, because nothing is recording yet).
- sp2-D2: `crash.log` is replaced by `main.log` with rotation (improvement). Nothing is written to `%LOCALAPPDATA%\MeetingLive`.
- sp2-D3: migrations (the library runtime) run before the window is created, because the IPC handlers read the library. Their error is queued and shown after the window is visible, which keeps the observable WinUI order.
- sp2-D4: `before-quit` fires even when the gate then says keep open, so the old bare `before-quit` listeners disposed the audio controller, transcription and detection after a vetoed quit while the user kept recording. They now run from `stopOnExit`, only on an approved quit.
- sp2-D5: the call watcher logs only the error type (`errorType`), as in item 150.
- sp2-D6: a settings file's unknown `uiLanguage` leaves English, matching the C# 'leave the culture alone'.

### Bugs fixed

- Bug 6: process-level errors reach `main.log`; a throwing fatal dialog no longer skips the exit.
- Bug 8: the close gate covers Preparing.
- Bug 10: measured, no change.
- Bug 21: a failing startup step is logged and shown once, not silent.
- Vetoed quit no longer disposes audio, transcription, summaries or detection (sp2-D4).

### Left for other modules

- sp-4: the shell dialogs for `recording.closeRequest` (confirm, saving, failed) are rendered by the renderer; the dialog UI, focus rules and the non-dismissable progress are checked there.
- sp-5: a packaged smoke of the close gate with a real recording; the migration error dialog in a real session (automated runs only log it).
- sp-3: the window scanner half of the section 6 group, and the migrations rows 6 to 8 (library runtime tests).
- live-copilot: the pill is not part of the watcher inventory; it must close with the main window through `handoff.registerSecondary`.

- e2e run by path: `shell-window.spec.ts`, `meeting-popup.spec.ts` and `library-close.spec.ts` pass (13 passed, 3 skipped).
- Not observed: a close with a real recording on screen, and the migration dialog in a visible window.
